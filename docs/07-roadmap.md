# 3〜5日の実行計画

最終更新: 2026-08-10

## 実行順

### 1. OSS 最小構成を clean start する

- サイト履歴や SaaS コードをコピーしない
- 問い合わせフォーム例、専用テスト、検証記録、OSS 文書を新規作成する
- remote の改名・作成・push は運営者の明示承認後

### 2. 一つのサンプルを作る

- `document.modelContext` を使う
- 日本語問い合わせフォームを通常UIとして残す
- Tool は入力または下書きまでに限定する
- 最終送信は人の確認後に行う

### 3. テストを作る

- Tool登録
- 日本語入出力
- 送信前確認
- WebMCP がない環境での通常UI

### 4. Chrome で検証する

- ネイティブ実装を優先する
- 実行日、OS、Chrome バージョン、flag、commit を記録する
- 期待結果と実結果を `results/` へ残す

### 5. クリーンチェック

- 新しい環境でセットアップから再実行する
- `npm test` / `npm run lint` を実行する
- 秘密情報、サイト固有コード、不要な生成物がないことを確認する

## 完了条件

- 一つのサンプルと再現可能なテストがある
- 環境情報付きの検証結果がある
- ライセンス、参加方法、外部投稿ルールが明記されている
- サイト / SaaS / GTM / 課金コードを含まない
